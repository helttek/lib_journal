# lib_journal

Многопоточная библиотека записи текстовых сообщений в журнал и консольное
приложение для её проверки. Выполнено на C++17 (STL, без сторонних
библиотек), целевая платформа — актуальные версии Ubuntu/Debian, компилятор —
GCC.

## Состав проекта

| Файл                        | Назначение                                       |
| --------------------------- | ------------------------------------------------ |
| `include/libjournal.hpp`    | публичный интерфейс библиотеки                   |
| `src/libjournal.cpp`        | реализация библиотеки                            |
| `src/ThreadSafeQueue.hpp`   | потокобезопасная блокирующая очередь с закрытием |
| `src/Application.{hpp,cpp}` | логика тестового приложения                      |
| `src/main.cpp`              | точка входа приложения                           |

## Сборка

```sh
make            # библиотека + приложение (цель all)
make lib        # только динамическая библиотека libjournal.so
make app        # только приложение test-lib-journal
make test       # автоматический прогон с проверками журнала
make clean      # удаление всех временных файлов
```

Объектные файлы и артефакты сборки создаются в корневом каталоге проекта.
Приложение связывается с динамической библиотекой через rpath `$ORIGIN`,
поэтому запускается без настройки LD_LIBRARY_PATH.

## Запуск

```
test-lib-journal <файл журнала> <уровень по умолчанию>
```

Уровень по умолчанию: `LOW`, `MIDDLE` или `HIGH`. Пример:

```sh
./test-lib-journal journal.txt MIDDLE
```

### Формат ввода

Каждая строка — отдельное сообщение:

```
[HIGH] Сервер недоступен          # сообщение с уровнем HIGH
обычное сообщение                 # уровень опущен — берётся по умолчанию
```

- уровень можно опустить;
- регистр не важен (`[low]`, `[Low]`, `[LOW]`);
- сообщения с уровнем **ниже** уровня по умолчанию в журнал не попадают;
- неизвестный уровень, незакрытая скобка и пустые строки отбрасываются
  с диагностикой в stderr.

Завершение работы — конец ввода (Ctrl+D); все принятые сообщения при этом
дописываются в журнал. Ctrl+C завершает процесс принудительно средствами
операционной системы.

## Формат журнала

Одна строка на сообщение: время получения, уровень важности, текст.

```
2026-08-22 13:25:40.204 [HIGH] one
2026-08-22 13:25:40.204 [MIDDLE] plain
```

Время фиксируется в момент передачи сообщения библиотеке (`Journal::log`),
а не в момент фактической записи на диск.

## API библиотеки

```cpp
#include "libjournal.hpp"

jnl::Journal journal("app.log", jnl::Priority::MIDDLE);

journal.log("сообщение с уровнем по умолчанию");
journal.log(jnl::Priority::HIGH, "критичное сообщение");

journal.set_default_priority(jnl::Priority::LOW); // меняется в любой момент
bool ok = journal.good();                         // false при ошибке записи
```

Библиотека динамическая (`libjournal.so`). Сообщения передаются фоновому
потоку записи через потокобезопасную очередь, поэтому `log()` не блокирует
вызывающий поток на дисковых операциях. Детали реализации скрыты за
указателем (pimpl), публичный заголовок не зависит от внутренних типов.

## Архитектура

- **Библиотека**: очередь `ThreadSafeQueue<Entry>` → фоновый поток записи.
  Уровень по умолчанию хранится в `std::atomic`, фильтрация выполняется на
  стороне вызывающего потока. Деструктор закрывает очередь и дожидается
  дописывания всех сообщений.
- **Приложение**: главный поток читает ввод; пул из трёх потоков-работников
  разбирает очередь задач и вызывает `journal.log()`. По концу ввода очередь
  закрывается, работники дописывают оставшиеся задачи и завершаются.

## Обработка ошибок

- невозможность открыть файл журнала — исключение при создании `Journal`;
- ошибки записи (диск переполнен, файл удалён и т.п.) фиксируются:
  однократно печатаются в stderr, `Journal::good()` возвращает `false`;
- некорректные параметры запуска и ввод пользователя отклоняются
  с диагностикой.
